# MT11. Provar i documentar una API

Micro-presentació docent breu per a `R4S5`. Equival aproximadament a `6` diapositives.

## Diapositiva 1. Idea central

- una API no està acabada si només funciona en el navegador
- cal petició reproduïble
- documentació i comportament han de coincidir

## Diapositiva 2. Prova mínima

- petició correcta
- resposta correcta
- credencial si cal
- cas sense permís
- cas amb dada incorrecta
- instrucció per repetir-la

## Diapositiva 3. Eines

- `curl`
- Postman o Bruno
- test automatitzat
- script curt
- col·lecció exportable

## Diapositiva 4. Documentació útil

- URL base
- endpoints
- headers
- exemples de body
- codis d'estat
- errors i límits

## Diapositiva 5. Evidència del dia

- dues peticions reproduïbles
- un cas d'error
- README o contracte actualitzat
- prova executada després del canvi
- commit de tancament

## Diapositiva 6. Tancament

- documentar una API és descriure el que fa, no el que voldries que fera
- el consumidor no ha d'endevinar formats
- pregunta final: quina petició pot copiar una altra persona per verificar la teua API?
